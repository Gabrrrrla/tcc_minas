## 1. O que foi implementado nesta sessão

### 1.1 CN-NSSMF — esqueleto (`agents/cn-nssmf/`)

Agente de domínio do núcleo 5G, conforme cap. 4 do TCC.

- `main.py` — servidor Flask: `POST /directive` (chamado pela ferramenta
  `invoke_cn_nssmf` do orquestrador, aponta para `http://cn-nssmf:8001`) +
  `GET /health`. Cada diretiva dispara um loop ReAct próprio. System prompt do
  domínio de núcleo (PCF/SMF/NWDAF, vocabulário 3GPP, as 4 ações de diretiva
  `apply_qos`/`revert_qos`/`query_nwdaf`/`check_sla`, regras de decisão incluindo
  degradação graciosa reportada ao orquestrador).
- `tools.py` — 5 ferramentas no formato Ollama + `dispatch_tool`:
  - `query_nwdaf` — **stub** (mock em `nwdaf_client.py`)
  - `configure_qos` — **stub** (monta o dict; `# TODO` PCF/SMF)
  - `revert_qos` — real (tabela `policies`)
  - `get_core_kpis` — real (tabela `core_kpis`)
  - `record_policy` — real (tabela `policies`)
- `nwdaf_client.py` — stub das interfaces normativas da NWDAF
  (`Nnwdaf_AnalyticsInfo`, `Nnwdaf_EventsSubscription`, TS 23.288). Retorna
  predição mock.

### 1.2 Orquestrador — virou serviço HTTP (`agents/orchestrator/`)

Antes era só CLI. `main.py` reescrito mantendo `run()` (loop ReAct) e o modo CLI
(`python main.py "<intenção>"`), e adicionando:

- `POST /intent` — body `{"intent": "..."}` → `{"outcome": "..."}`
- `GET /health`
- **sem argumentos → sobe o servidor** na porta 8000
- trava `REACT_MAX_STEPS` (16) no loop, pra não travar request em loop infinito

Agora o `invoke_cn_nssmf` alcança o `cn-nssmf:8001` pela rede `minas-net`.

### 1.3 Collector de KPIs (`agents/collector/`) — novo

Não é um agente do TCC; é plumbing. **Amostrador de série temporal**: a cada
`COLLECT_INTERVAL` segundos grava uma linha por slice em `core_kpis` **e**
`ran_kpis`, pra que as ferramentas de leitura dos agentes e o modelo preditivo da
NWDAF tenham histórico. A leitura do *estado atual* continua sendo ferramenta
dentro de cada agente; o collector constrói o *histórico*.

Fonte plugável por tabela:

| env | valores | default |
|---|---|---|
| `CORE_SOURCE` | `prometheus` \| `mock` | `prometheus` |
| `RAN_SOURCE` | `prometheus` \| `o1` \| `mock` | `mock` |

- `prometheus` — HTTP API do Prometheus sobre os exportadores Open5GS. As PromQL
  em `QUERIES_CORE`/`QUERIES_RAN` são **chutes** (`# TODO` confirmar com
  `curl smf:9090/metrics`). Open5GS 2.6.4 quase não rotula métrica por slice →
  hoje o agregado vai pra todas as slices. RAN por Prometheus só aproxima
  throughput pelos contadores N3 da UPF (HANDOVER-2026-08-25 "Opção 1");
  RSRP/SINR/MCS/PRB ficam `NULL`.
- `o1` — `o1_client.py`, **stub**. É o caminho **ideal** para RAN: NETCONF/YANG
  contra o gNB, puxando performance measurements por S-NSSAI (TS 28.552).
  Levanta `NotImplementedError`; o loop pula a linha sem quebrar. Bloqueado na
  resposta do Miguel sobre o software do gNB.
- `mock` — linhas sintéticas, pra desenvolver antes das métricas reais.

## 3. O que falta — visão completa

### 3.1 Agentes que não existem

- **RAN-NSSMF**: servidor HTTP `/directive` (:8002) + ReAct + ferramentas
  (ler `ran_kpis`/PromQL, ajustar PRB/alocação por slice, `revert`, reportar
  SLA) + serviço no compose. Sem ele, `invoke_ran_nssmf` falha e o **UC2 não roda**.
  Pode partir do mesmo esqueleto do CN-NSSMF.
- **NWDAF**: serviço com Random Forest treinado sobre séries de telemetria,
  horizonte 60 s, expondo algo tipo `Nnwdaf_AnalyticsInfo` que o `query_nwdaf`
  do CN-NSSMF consuma. TCC também pede comparação com Gradient Boosting e LSTM.

### 3.2 Stubs a substituir

- `cn-nssmf` `configure_qos`: enforcement real no **PCF** (PCC rule, 5QI, ARP) e
  **SMF** (Session-AMBR, QoS Flow GBR/MBR) — editar `pcf.yaml`/`smf.yaml` ou API
  do Open5GS + reload da NF.
- `cn-nssmf` `_current_qos`: ler config viva do PCF/SMF (hoje mock) — sem isso o
  `revert_qos` não restaura de verdade.
- `cn-nssmf/nwdaf_client.py`: chamada HTTP real quando a NWDAF existir.
- `collector/o1_client.py`: NETCONF/YANG (ncclient) quando souber o software do gNB.
- `collector` `QUERIES_CORE`/`QUERIES_RAN`: confirmar nomes/labels com
  `curl <nf>:9090/metrics`; resolver mapeamento **por slice** (`snssai`).

### 3.3 Orquestrador — lacunas

- **Reversão por janela temporal**: nada agenda o revert das 22h. UC2 precisa de
  um scheduler (job que dispara `revert` nos dois agentes ao fim da janela).
- **RAG** sobre TS 28.312 / TS 23.288 (o TCC pede) — nenhum agente tem.
- **Benchmark de seleção de modelo LLM** sobre intents derivadas da TS 28.312 —
  não feito; `llama3.1:70b` é chute.

### 3.4 Infra

- Fonte de métrica de RAN não existe no stack (Prometheus só raspa amf/smf/upf).

- Agentes não expõem métricas próprias (latência de decisão, acurácia de
